# Комплексный отчет: Эволюция ИИ и оптимизация Anti_VS

В данном документе зафиксированы все ключевые архитектурные решения, изменения алгоритмов ИИ, математические формулы фитнеса и оптимизации производительности движка, выполненные в ходе работы над проектом.

## 1. Новая сенсорная система Босса (150 входов)

### Предыстория и проблема
Ранее Босс использовал грубую 8-секторную круговую модель («ромашка»), где снаряды и мобы сливались в общую массу. Босс не мог видеть безопасные коридоры между летящими снарядами и не различал угрозу от дальних снайперов за пределами экрана.

### Архитектура Dual-Ring Sensor Grid
Разработана и внедрена гибридная система наблюдения из 150 скалярных признаков:
```
+---------------------------------------------------------+
|     ВНЕШНИЙ МАКРО-ПОЯС (16 секторов, радиус 500 px)      |
|                                                         |
|         +-------------------------------------+         |
|         |  ВНУТРЕННЯЯ СЕТКА (11x11, 50 px)     |         |
|         |  Охват 550x550 px вокруг Босса      |         |
|         |  - Снаряды (вес 2.5x)               |         |
|         |  - Ближние мобы                     |         |
|         |             [ БОСС ]                |         |
|         +-------------------------------------+         |
|                                                         |
|  - Директ-векторы на культистов и снайперов             |
+---------------------------------------------------------+
```

1. **Внутренняя локальная сетка ($11 \times 11 = 121$ ячейка, шаг 50 px, охват $550 \times 550$ px)**:
   * Каждая ячейка суммирует угрозы: мобы + летящие снаряды (с приоритетным множителем $2.5\times$).
   * Дает пространственное микро-зрение для ювелирного стрейфа между снарядами культистов и камикадзе.
2. **Внешний макро-пояс (16 секторов, дальность до 500 px)**:
   * Фиксирует плотность снайперов и дальнобойных культистов, готовящих залп издалека.
3. **Стратегические скаляры навигации (13 входов)**:
   * Координаты и расстояние до центра арены ($dx, dy, dist$).
   * Дистанции отталкивания от 4 силовых границ арены (220 px буфер).
   * Прогресс раунда ($time / 1020$).
   * Текущее состояние здоровья Босса ($HP / MaxHP$).
   * Статус медитации ($timer / 3.0$).
   * Вектор собственной скорости движения.

**Нейросеть Босса:** Полностью масштабирована на топологию $150 \to 128 \to 64 \to 8$ (2,368 синапсов), компилируется без аллокаций памяти за счет плоских массивов и SIMD.

## 2. Полная автономия решений ИИ (Удаление эвристик)

Ранее часть ключевых решений принималась захардкоженными правилами (`if/else`). Они были полностью удалены в пользу обучения с подкреплением (RL):

* **Тактическая медитация**: Удалены искусственные флаги `wants_meditation = true` (например, "медитировать если Full HP и мобов < 3"). Теперь решение о медитации полностью принимает 8-й выход нейросети: `nn_out[7] > 0.60`. В формулу фитнеса добавлен бонус за осознанную медитацию.
* **Автономия рывка (Dash)**: Убран костыль `mobs_in_close_radius >= 4`. Рывок активируется нейросетью (`nn_out[6] > 0.70`), а направление определяется вектором уклонения и физикой потенциальных полей.
* **Драфт перков (Perk Draft)**: Удалены костыли прокачки («если мало HP -> брать GiantHeart», «если бьют вблизи -> LightArmor»). Выбор перков теперь на 100% управляется ДНК-весами 6 синергетических архетипов:
  1. *Инфернальный Пиромант* (Огонь, Пламя, Сердце Пироманта)
  2. *Сверхпроводящий Громовержец* (Молния, Тесла, Лира, Клевер)
  3. *Несокрушимый Бастион* (Орбиты, Молот, Щиты, Эгида)
  4. *Аннигилятор Бездны* (Луч Смерти, Сингулярность, Око Колосса)
  5. *Кровавый Жнец* (Топор, Кинжалы, Вампиризм, Клевер)
  6. *Звёздный Охотник* (Лук, Ракеты, Самонаведение, Орлиный Глаз)

## 3. Детализированная телеметрия урона

В модуль `src/ecs/components/inventory.rs` внедрена структура детального учета урона:
* **Категории источников (`DamageSourceKind`)**:
  * `Melee` (контактные атаки мобов)
  * `Ranged` (стрелы, файрболы, снаряды)
  * `Hazard` (кислотные лужи, споры, взрывы камикадзе)
* **Типы повреждений (`DamageTypeBreakdown`)**: Физический, Огонь, Холод, Яд, Святой, Чистый урон.
* Данные выводятся в лог раунда, что позволяет мгновенно видеть причину гибели Босса.

## 4. Оптимизация производительности игры и симуляции

1. **Условный параллелизм (`is_headless`) в `src/ecs/systems/movement.rs`**:
   * *В режиме обучения (Headless)*: 8–16 симуляций уже идут параллельно по ядрам CPU (`into_par_iter()`). Внутри каждой симуляции мобы обновляются последовательно через `iter_mut()`, устраняя накладные расходы Rayon на создание подзадач.
   * *В интерактивной игре*: Включается `par_iter_mut()`, задействуя все потоки процессора для плавной отрисовки тысяч мобов.
2. **Frustum Culling (Отсечение невидимого)**:
   * В `src/render/renderer.rs` добавлена проверка попадания объектов в экран камеры `in_view(pos, radius)`. Невидимые за границами экрана мобы, снаряды, лужи и частицы больше не отправляются на отрисовку в GPU (сокращение вызовов отрисовки на 60–80%).
3. **Кластеризация кристаллов душ (Soul Gem Clustering)**:
   * При превышении 350 кристаллов на карте близколежащие кристаллы объединяются в крупные кластеры с полным сохранением накопленного XP.

## 5. Вычислительные мощности: Local Ryzen vs Colab

| Параметр | Google Colab (Free Tier) | Локальный ПК (AMD Ryzen 5 7520U) |
| :--- | :--- | :--- |
| **Вычислитель** | 2 vCPU (виртуальные потоки) | **4 ядра / 8 физических потоков** |
| **Частота** | ~2.20 GHz (Intel Xeon / EPYC) | **До 4.30 GHz (Boost, TSMC 6nm)** |
| **Архитектура Anti_VS** | CPU Rayon Multi-threading | CPU Rayon Multi-threading |
| **Скорость симуляции** | Базовая | **в 4–5 раз быстрее** |
| **Лимиты по времени** | Сессия сбрасывается, тайм-аут | **Без ограничений** |

* В Google Colab правильный выбор среды — **ЦП (CPU)**, так как симуляция Rust ECS не использует GPU-шейдеры, а выбор GPU только расходовал бы квоты.
* Для сборки на Windows решена проблема отсутствия линкера MSVC `link.exe`.
* Ноутбук `Anti_VS_Colab_Trainer.ipynb` оптимизирован под запуск в 1 клик.

## 6. Устранение Reward Hacking (Взлом наград) и баланс со-эволюции

### Обнаруженная проблема
В ходе анализа логов раунда было замечено, что Директор затягивал бой до 11.7 минут вместо быстрого добивания. Причина: Директор получал очки за суммарный урон (`damage * 0.06`). Раскармливая регенерирующего босса, Директор набивал **39,000 HP урона** и получал **+2341 очко фитнеса**, что перекрывало штраф за затяжку.

### Внесенные корректировки в `src/ai/trainer.rs`
1. **Бонус за ранний конец матча (Блицкриг)**:
   * Множитель сохраненного времени поднят с 3.0 до **5.0** (до 5,100 очков).
   * Бонус за убийство повышен с 800 до **1,500** очков.
   * Добавлен блицкриг-бонус при победе быстрее 5 минут: `(300с - t) * 5.0`.
2. **Ужесточение штрафов за затягивание боя**:
   * Порог штрафа опущен с 7 до **5 минут (300с)**.
   * Ставка штрафа увеличена до **-4.0 очка в секунду**.
   * Штраф за полное выживание Босса (17 минут) увеличен с 800 до **2,500** очков.
3. **Потолок на урон**:
   * Награда за урон ограничена жестким потолком в **500 очков**, устраняя эксплойт фарма регенерации.

## 7. Редизайн логов и Tournament League Self-Play

1. **Очистка от эмодзи**: Удалены десятки повторяющихся смайликов мобов, лог приведен к чистому профессиональному виду.
2. **Фокус на «Время жизни босса» (в минутах)**:
   ```text
   ================================================================================
   >>> РАУНД 01/20 (Поколение #01) [Зал Славы: 1 моделей]
   --------------------------------------------------------------------------------
     [ВРЕМЯ ЖИЗНИ БОССА В РАУНДЕ]:
       >> В матчах лучшего Босса:      9.5 мин (570.3 сек)  [цель: 17.0 мин]
       >> Против лучшего Директора:    3.8 мин (228.0 сек)  [цель: 0.0 мин]
   --------------------------------------------------------------------------------
   ```
3. **League Self-Play (Зал Славы)**:
   * Двое лучших Боссов и двое лучших Директоров переходят в новое поколение напрямую (элитизм).
   * Каждый участник проводит 3 боя: 2 против текущей популяции и 1 гарантированный бой против исторического чемпиона из **Зала Славы (до 12 моделей)** для защиты от забывания тактик.
4. **Чистый старт**: Удалены устаревшие файлы моделей из `models/`, обучение запускается с чистого листа с поколения #01.
